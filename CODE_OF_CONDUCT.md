# Code of Conduct

## Our Pledge

We as contributors, maintainers, and community members pledge to make participation in this project a harassment-free experience for everyone, regardless of age, body size, visible or invisible disability, ethnicity, sex characteristics, gender identity and expression, level of experience, education, socioeconomic status, nationality, personal appearance, race, caste, color, religion, or sexual identity and orientation.

We pledge to act and interact in ways that contribute to an open, welcoming, diverse, inclusive, and healthy community.

---

## Our Standards

**Examples of behavior that contributes to a positive environment:**

- Using welcoming and inclusive language
- Being respectful of differing viewpoints and experiences
- Gracefully accepting constructive criticism
- Focusing on what is best for the community
- Showing empathy toward other community members
- Acknowledging the contributions of others
- Helping newcomers get oriented and feel welcome

**Examples of unacceptable behavior:**

- The use of sexualized language or imagery, and sexual attention or advances of any kind
- Trolling, insulting or derogatory comments, and personal or political attacks
- Public or private harassment
- Publishing others' private information (physical or email addresses) without explicit permission
- Dismissing or belittling contributions because of someone's experience level
- Sustained disruption of discussions, issues, or pull requests
- Other conduct which could reasonably be considered inappropriate in a professional setting

---

## Scope

This Code of Conduct applies to all project spaces — including the GitHub repository, issues, pull requests, discussions, and any other communication channels associated with this project. It also applies when an individual is representing the project in public spaces.

---

## Enforcement

Instances of abusive, harassing, or otherwise unacceptable behavior may be reported by opening a GitHub issue or contacting the project maintainers directly. All complaints will be reviewed and investigated promptly and fairly.

Maintainers are obligated to respect the privacy and security of the reporter of any incident.

**Enforcement actions may include:**

1. **Correction** — A private written notice explaining the nature of the violation and why the behavior was inappropriate.
2. **Warning** — A formal warning with consequences for continued behavior.
3. **Temporary suspension** — A temporary ban from any interaction or public communication within the project spaces.
4. **Permanent ban** — A permanent ban from any public interaction within the project community.

## Contribution Guidelines

### Submitting Issues

- Search existing issues before opening a new one.
- Provide a clear, descriptive title.
- Include enough context for maintainers to reproduce or understand the problem.
- For documentation errors, quote the specific passage and explain what is incorrect or misleading.

### Submitting Pull Requests

- Fork the repository and create your branch from `main`.
- Keep pull requests focused — one concern per PR.
- Write a clear description of what the change does and why.
- For content changes to authorization model documents, reference sources or standards where applicable.
- For new authorization models, follow the existing 18-section document structure.

### Content Standards

This is a technical reference repository. Contributions to documentation must meet the following standards:

- Technically accurate. Do not introduce unsupported claims, invented standards, or fabricated library capabilities.
- Framework-agnostic. Avoid coupling explanations to specific frameworks unless the concept cannot be demonstrated otherwise.
- Consistent terminology. Use terminology consistently within and across documents.
- Clearly distinguish authentication from authorization.
- Prefer concrete examples over vague generalizations.

### Reporting Inaccuracies

If you find a technical inaccuracy, a missing security consideration, or a misleading explanation, please open an issue with:

- The document name and section
- The specific claim that is inaccurate or incomplete
- A correction or reference to a primary source

## AI-Generated Content Notice

> **Important:** The documentation in this repository was generated with the assistance of an AI language model.
>
> While every effort has been made to ensure technical accuracy, AI-generated content can contain mistakes, outdated information, subtle inaccuracies, or oversimplifications — especially in security-critical domains.
>
> **Do not treat any document in this repository as a substitute for:**
> - A formal security review by a qualified security engineer
> - Consulting primary sources (NIST SP 800-162 for ABAC, the Zanzibar paper for ReBAC, vendor documentation for specific implementations)
> - A penetration test or security audit of your actual implementation
>
> If you find an error, please open an issue. Corrections from human experts are strongly encouraged and will be prioritized.
